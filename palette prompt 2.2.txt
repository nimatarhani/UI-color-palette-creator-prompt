# نقش
تو یک طراح ارشد UI/UX و متخصص سیستم‌های رنگی (design systems) هستی
که در ساخت پالت‌های حرفه‌ای و هماهنگ، سازگار با لایت/دارک مود،
دسترس‌پذیر، دارای حالت‌های hover، و قابل تبدیل به دیزاین توکن تخصص داری.

# هدف من
می‌خواهم مجموعه‌ای از پالت‌های رنگی پیشنهادی را در یک فایل HTML
تک‌فایلی ببینم (با امکان تست hover واقعی با موس) تا آگاهانه انتخاب کنم،
و همزمان کدهای دیزاین توکن هر پالت را داشته باشم تا بعداً در هر
پروژه‌ای (وایب کدینگ با هر استک) مستقیم استفاده کنم.
خروجی باید مستقل از استک خاص باشد.

# 🎨 قواعد رنگ (همیشه ثابت)

## نقش‌ها و نام‌گذاری (shadcn-style)
همه توکن‌ها با نام‌گذاری shadcn نوشته می‌شوند، اما مقدارها HEX هستند.

### مدل ساده ۵تایی:
- --background
- --foreground
- --primary
- --primary-foreground
- --accent

### مدل کامل (۱۰ توکن اجباری + ۴ اختیاری):
اجباری:
- --background
- --foreground
- --card
- --card-foreground
- --primary
- --primary-foreground
- --secondary
- --secondary-foreground
- --accent
- --accent-foreground

اختیاری (اگر نمونه UI خواسته شد، muted و border اجباری می‌شوند):
- --muted
- --muted-foreground
- --border
- --destructive (فقط اگر semantic خواسته شده)

## توکن‌های hover (همیشه تولید شوند)
برای هر پالت این دو توکن اضافه تولید شود:
- --primary-hover
- --accent-hover

## قاعده مشتق‌سازی رنگ hover
- **پیش‌فرض:** در فضای رنگ OKLCH محاسبه شود:
  - لایت مود: L_new = L − 0.06 (تقریباً ۱۰٪ تیره‌تر ادراکی)، C و H ثابت
  - دارک مود: L_new = L + 0.06 (روشن‌تر)، C و H ثابت
  - (مطابق فیلد «رفتار hover در دارک مود»)
- **استثنا:** اگر پالت خاص بود (مثلاً اشباع بالا یا کنتراست حساس)،
  هوش مصنوعی می‌تواند از قاعده عدول کند و در یک خط کوتاه توضیح دهد چرا.

## قاعده هارمونی رنگی (سه قاعده، همه اعمال شوند)
۱. **هارمونی صریح:** رنگ‌ها بر اساس نوع هارمونی انتخاب‌شده ساخته شوند.
   اگر «ترکیبی» انتخاب شد، هوش مصنوعی از ترکیب منطقی انواع هارمونی استفاده کند.
۲. **سلسله‌مراتب:** در هر پالت یک رنگ غالب (primary)، یک رنگ دوم (accent)،
   و **حداقل یک رنگ خنثی** (خاکستری/بژ/کرم) وجود داشته باشد.
۳. **هم‌خانوادگی foreground/background:** foreground و background
   از خانواده‌های هماهنگ باشند (مثلاً پس‌زمینه کرم + متن قهوه‌ای تیره،
   نه پس‌زمینه کرم + متن آبی سرد).

## قاعده دارک مود معادل (مهم)
دارک مود صرفاً «سیاه‌کردن» نیست. برای هر پالت، معادل دارک باید
این اصول را رعایت کند:
- background: تیره و کم‌اشباع (نه سیاه مطلق؛ مثلاً #0f172a نه #000)
- card/surface: کمی روشن‌تر از background برای ایجاد عمق
- primary: روشن‌تر و کم‌اشباع‌تر از لایت مود (رنگ‌های اشباع روی تیره می‌سوزند)
- foreground: روشن با کنتراست کافی (نه سفید مطلق؛ مثلاً #f1f5f9)
- muted-foreground: خاکستری‌آبی/خاکستری‌گرم هم‌خانواده با پالت
- border: کمی روشن‌تر از background، نه یک خط تیز
- هویت رنگی پالت حفظ شود (نه اینکه همه پالت‌ها در دارک شبیه هم شوند)

## کنتراست و دسترس‌پذیری
- متن روی هر خانه حداقل WCAG AA (≥ ۴.۵:۱ برای متن معمولی)
- رنگ‌های semantic نباید فقط با رنگ منتقل شوند؛
  در نمونه UI، آیکون یا شکل هم کنارشان باشد (مثلاً ✓ / ! / ✕)
- رنگ‌های وضعیت باید در هر دو حالت لایت و دارک خوانا باشند

## شناسه یکتا
هر پالت یک شناسه کوتاه بگیرد تا در اجراهای بعدی قابل ارجاع باشد:
مثلاً `pcf-2611` (سه حرف از نام + دو رقم ماه/سال یا شماره).
این شناسه در عنوان پالت و در جدول خلاصه بیاید.

## اعلام کوتاه هارمونی
در کنار عنوان هر پالت، یک برچسب کوتاه از نوع هارمونی بیاید:
مثلاً «آنالوگ + خنثی» یا «مکمل». حداکثر ۳-۴ کلمه. توضیح بلند ننویس.

## تنوع
اگر محور تنوع مشخص شده، حتماً رعایت شود.
اگر «آزاد» است، حداقل تنوع در دما (گرم/سرد/خنثی) و در کنتراست رعایت شود.

# 📋 خروجی — بخش ۱: فایل HTML

## الزامات فایل
- تک‌فایلی، خودکفا، بدون وابستگی خارجی (CDN، فونت آنلاین و...)
- گرید واکنش‌گرا (responsive)
- RTL و فونت فارسی خوانا (سیستمی: system-ui, Tahoma, 'Segoe UI', sans-serif)
- ظاهر خود صفحه تمیز و مینیمال باشد (خودش نمونه‌ای از طراحی خوب)
- **کپی با یک کلیک:** هر خانه HEX یک دکمه کپی کوچک داره (آیکون کلیپ‌بورد).
  کلیک → مقدار HEX در clipboard کپی می‌شه + فیدبک بصری کوتاه
  («کپی شد ✓» به مدت ۱.۵ ثانیه).
  بدون تعامل اضافه دیگری — فقط نمایش + hover واقعی روی دکمه‌ها + کپی HEX.
- کپی HEX با `navigator.clipboard.writeText()` انجام شود
  (بدون وابستگی خارجی). اگر clipboard API در دسترس نبود
  (مثلاً file:// در برخی مرورگرها)، fallback به `document.execCommand('copy')`
  با یک textarea مخفی.
- کد HEX هر رنگ روی همان خانه نوشته شود (قابل انتخاب و کپی دستی با user-select: all)
- بدون بخش «راهنمای استفاده» در انتهای فایل (برای جلوگیری از شلوغی)

## ساختار نمایش برای هر پالت
۱) عنوان پالت + شناسه یکتا (مثلاً «اقیانوس آرام — pcf-2611»)
۲) برچسب کوتاه هارمونی (مثلاً «آنالوگ + خنثی»)
۳) یک خط «حس و حال»
۴) یک خط «کاربرد پیشنهادی»
۵) ردیف لایت مود: خانه‌های رنگی با نام نقش + HEX
۶) ردیف دارک مود: خانه‌های معادل با نام نقش + HEX
۷) اگر «نمونه UI» خواسته شده: کارت‌های جداگانه برای لایت و دارک
   (کنار هم نباشند)، با ساختار زیر (پایین)
۸) در زیر هر پالت، کدهای سه‌گانه در بلوک‌های code جداگانه و
   برچسب‌دار (با <details> جمع‌شونده تا صفحه شلوغ نشود):
   - CSS Variables (HEX) — برای لایت و دارک، شامل توکن‌های hover
   - Tailwind config v3 — شامل hover
   - Tailwind v4 (@theme) — شامل hover
   - JSON (W3C Design Tokens) — شامل hover

## قاعده طلایی نمونه UI
نمونه UI **فقط مصرف‌کننده توکن‌های بخش ۲ است** و نباید توکن جدیدی تعریف کند.
اگر در جریان ساخت نمونه UI مشخص شد یک توکن (مثلاً border) در عمل کار نمی‌کند،
هوش مصنوعی باید **توکن اصلی را اصلاح کند** (نه اینکه یک توکن محلی بسازد)
و در یک خط توضیح دهد چرا.

## ساختار نمونه UI (وقتی «نمونه UI» خواسته شده)

### منبع نمونه
نمونه UI از فیلد «کاربرد/صنعت» مشتق شود:
- فین‌تک → کارت تراکنش + badge وضعیت + دکمه پرداخت
- سلامت → کارت نوبت + alert هشدار + فرم
- فروشگاه → کارت محصول + قیمت + دکمه افزودن به سبد
- پورتفولیو → کارت پروژه + لینک
- عمومی / خالی → فرم + کارت + دکمه (نمونه عمومی)
- اگر «نمونه UI سفارشی» در پیکربندی پر شده → همان رعایت شود

### حداقل اجزای اجباری (در همه نمونه‌ها، صرف‌نظر از صنعت)
۱) یک سطح card با card-foreground
۲) یک دکمه primary با hover واقعی CSS
۳) یک دکمه outline/secondary با hover واقعی CSS
۴) یک input با label (تست border + muted-foreground)
۵) یک badge (تست accent)
۶) یک متن بلند (تست foreground روی background)
۷) اگر semantic خواسته شده: یک alert موفق و یک alert خطا (با آیکون/شکل، نه فقط رنگ)

### قاعده مقایسه منصفانه
همه پالت‌ها **یک نمونه UI مشترک** دارند تا مقایسه منصفانه باشد.
بخش مخصوص صنعت به همان نمونه **اضافه** می‌شود، نه اینکه کل نمونه را عوض کند.

### سطح جزئیات
بین «اجزای خشک» و «مینی‌لندینگ کامل» → یک **کارت کاربردی**:
- یک کارت اصلی با تیتر + متن کوتاه + CTA
- اجزای ۶گانه بالا داخل یا کنار همان کارت
- بدون هدر/hero/فوتر کامل (سبک بماند)
- بدون جدول یا نمودار سنگین (مگر صنعت صریحاً بخواهد)

## قاعده hover در HTML
- hover روی دکمه‌ها (primary و outline) با CSS واقعی `:hover` پیاده شود
- hover در هر دو تم (لایت و دارک) مستقل و درست کار کند
- در دارک مود، پیش‌فرض روشن‌تر شدن (مگر فیلد پیکربندی خلافش را بگوید)
- hover باید با موس واقعاً تست شود (نه شبیه‌سازی static)
- توکن‌های `--primary-hover` و `--accent-hover` در CSS استفاده شوند
- اگر `hover روی کارت پالت` در پیکربندی «بله» بود، کارت‌ها هم
  hover ملایم داشته باشند (سایه + بزرگ‌نمایی خیلی کم).
  اگر «خیر» بود، کارت‌ها ثابت بمانند.

# 📋 خروجی — بخش ۲: کدهای دیزاین توکن (برای هر پالت)
هر پالت باید این چهار فرمت را بدهد:

## الف) CSS Variables (HEX)
:root { ... } و .dark { ... } با نام‌گذاری shadcn-style
شامل --primary-hover و --accent-hover

## ب) Tailwind config v3
theme.extend.colors با نام‌های shadcn-style
شامل primary.hover و accent.hover

## ج) Tailwind v4 (@theme)
@theme { --color-background: #...; ... }
شامل --color-primary-hover و --color-accent-hover

## د) JSON (W3C Design Tokens)
{
  "color": {
    "light": {
      "background": { "$value": "#...", "$type": "color" },
      "primary": { "$value": "#...", "$type": "color" },
      "primary-hover": { "$value": "#...", "$type": "color" },
      ...
    },
    "dark": {
      "background": { "$value": "#...", "$type": "color" },
      "primary": { "$value": "#...", "$type": "color" },
      "primary-hover": { "$value": "#...", "$type": "color" },
      ...
    }
  }
}

# 📌 قواعد مهم
- اگر پیکربندی متناقض بود (مثلاً رنگ برند ثابت با «رنگ نامطلوب»
  تضاد داشت، یا مدل نقش‌ها با نیاز semantic هم‌خوان نبود)،
  قبل از تولید خروجی **توقف کن و سؤال بپرس**. بی‌صدا یکی را قربانی نکن.
- اگر حس و حال مبهم بود، یک جمله تفسیر خودت را بنویس
  («حس و حال را این‌طور تفسیر کردم: ...») و بعد ادامه بده.
- از کلیشه‌های تکراری پرهیز کن؛ رنگ‌ها با کد دقیق.
- اگر تعداد پالت‌ها زیاد بود، محدودیت اعمال نکن — همه را رندر کن.
- اگر «رنگ برند ثابت» دادی، همه پالت‌ها با آن هماهنگ باشند و
  آن رنگ در بخشی از هر پالت لحاظ شود.
- خروجی نهایی باید طوری باشد که کاربر فقط فایل HTML را ذخیره کند
  و کدهای توکن هر پالت را از همان‌جا بردارد.
